[a0.5.1] - 2026-10-21

本版本主题:机器码要稳定。修掉一个在多网卡环境(Docker / 面板 / 远程桌面都会装虚拟网卡)下会让官方许可证「时好时坏」的缺陷。

修复

  • 机器码在多网卡机器上不稳定:MachineCode 以前取「第一块有 MAC 的网卡」,而 GetAllNetworkInterfaces() 的返回顺序在不同进程间不保证一致 —— 同一台机器两次运行可能选到不同网卡,算出的机器码不同,官方许可证、封禁记录都会时对时错

- 现在按 MAC 排序后取第一块(不用网卡名排序,因为服务器上多块网卡常同名如「以太网」)

- 影响面:客户端、子服务端、官方服务端、许可证工具,四处共用同一份实现

改进

  • ZincXManagerTests 纳入交付包:官方服务端 / 子服务端 / 客户端 / 许可证工具 之外,多一个「5-全量测试」目录,双击即跑 12 套件 91 项
  • 打包前先跑测试:_build-installer.ps1 在出 MSI 之前跑一遍全量,不绿就不许打包

说明

  • 机器码算法变了,已经在用的机器码会变一次。受影响的封禁记录与已签发的 official.lic 需要按新机器码重签一次
  • 签许可证时的机器码请以目标机器上 ZincXManagerLicTool machine(新版)的输出为准

[a0.5.1] - 2026-10-21

连接可靠性:修掉「重复连接 / 连错目标」这一组问题,避免服务端挂一堆僵尸连接。

修复

  • 重复点「连接」不再叠加连接:同一目标已经连着时改为弹窗提示「已经连接」;换了地址/端口/模式才先断开再连新目标
  • 连接前先关旧连接:开始新连接前会关闭上一条,不再在服务端留下僵尸连接
  • 客户端单实例:同时只能开一个客户端,开第二个会自动退出
  • OOBE 连接按钮没按模式选目标:选 OOS 却用子服务端地址(czip)去连;现在连接窗口与 OOBE 都先按模式设目标(OOS → ozip/ozport)
  • OOBE 数据源页按模式显示地址:OS/SAOS 填子服务端,OOS 填官方服务端
  • OOBE 换目标会重连:先连 ZXMS 再改选 OOS 时,先断开再连官方端
  • 连接流程窗口不再重复弹出:已打开就置顶,不再新建

打包

  • 安装包 / 便携 ZIP 现在都带 UpdateLog.MD,客户端的更新日志页签不再空白
