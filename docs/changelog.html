  • 老客户端只读 7 段照样能用,解析不到消息号时按 0 处理(不参与补发去重)。
  • ZXMOS 服务端消息存档 messages.json:每条公告 / 推送分配一个消息号(从 1 递增)并落盘;

  • 两种新定向形态(push 的目标段):
  • push @server:<子服务端账号> —— 只投给那台 ZXMS 自己,它自己消费(控制台带边框醒目打印 + 记日志),
  • 不下发给它名下的客户端;
  • push @clients:<子服务端账号> —— 只投给那台 ZXMS,由它转发给自己名下所有客户端。
  • 补发链路(新增三个协议包,登录后自动补齐"还没收到过的消息"):
  • MessageHistoryReq = 505(客户端 → 服务端,登录成功后发一次):负载 client(替玩家要)/ self(子服自己来要);
  • MessageHistory = 504(服务端 → 客户端):一条消息一个包,负载就是那张卡片(第 8 段带消息号),
  • 正文里有换行也不会坏,不用按行切分;
  • MessageHistoryDone = 506(服务端 → 客户端):负载 = 补发条数,收尾用。
  • 补发按请求者身份过滤(ZXMOS 侧):公告 / @all 谁都能收;@server:<子服> 只在那台子服自己来要时给,
  • 而且绝不转给玩家;@clients:<子服> 只在那台子服替它名下的客户端来要时给;
  • 点名叫玩家的,直连客户端只认自己的名字,经子服的就全给它(它按自己的在线名单过滤)。没通过账号认证的子服不给补发。
  • ZXMS 中转:收到客户端的 505 → 分配一个中转包 Id(与账号中转同一套计数器,保证唯一)转给 ZXMOS;
  • ZXMOS 回的 504 逐条、506 收尾都按包 Id 找到"是哪条客户端连接要的"再原样转回去,收到 506 就清掉记录;
  • 官方服务端没连上 / 转发失败时立刻回一条 506 让客户端收尾,不干等。
  • 客户端去重:本地 messages.json 每条消息新增 serverId 字段,按「来源 + 消息号」去重 ——
  • 补发重复收到的不再重复显示,所以老客户端不会重复弹、新客户端一条不落。
  • 升级前存的老存档(没有 serverId 字段)会从卡片第 8 段把消息号补回来,一样能去重,不需要迁移数据。
  • 请求时机:登录成功时发一次 + 主窗口开起来(收包事件挂好)再发一次,两条路径互为兜底,重复的部分由去重吃掉。

  • push @all 其实是坏的(帮助里写了、代码里没实现):官方服按账号名过滤 → 没人匹配;子服也当玩家名去过滤 → 谁都收不到。
  • 三处补齐:@all 在官方服 = 直连客户端不做账号核对、在子服 = 转给本服所有客户端、在客户端 = 不再按账号丢掉。

  • 现在 MessageArchive.Add 收的是"拿到号之后再拼卡片"的写法,存档与发出去的是同一张。
