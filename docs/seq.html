握手、登录、消息、加密的逐步时序图。

文档中心 技术文档

第 3 页:协议时序

每个场景一张表:谁发、谁收、用哪个码、负载长什么样、这一步在干什么。码后面的数字就是包类型(见第 1 页协议码表)。

链路总览:ZXMOS(官方,25000) ⇄ ZXMS(子服,czport) ⇄ ZXMC(客户端);官方消息逐跳转发,子服不解析公告正文。

A. 客户端连上子服并登录

ZXMC 是图形客户端:连上 TCP 后先握手(300/301),拿服务端身份(200/201),再登录(600/601),登录成功后服务端补一次配置(202)和一次历史(505→504×N→506)。

步发送端接收端协议码负载这一步做什么
1ZXMCZXMS300 ConlineZXMC:<模式>客户端上线;ZXMS 记录这条连接,此时还没算登录
2ZXMSZXMC301 CBack—收到,握手完成
3ZXMSZXMC200 ServerIdentZXMS我是谁
4ZXMSZXMC201 ServerName服务端显示名客户端标题栏显示这个名字
5ZXMCZXMS600 AccountLogin名称|密码密文|等级登录请求(密码不是明文)
6ZXMSZXMC601 AccountLoginAckok|名称|ID|等级 或 err|原因成功/失败
7ZXMSZXMC202 ServerConfigmsgdays=天数登录成功后补一次,告诉客户端本地留多久
8ZXMCZXMS505 MessageHistoryReqclient / self / 空客户端要历史
9ZXMSZXMC504 MessageHistory卡片原文(第 8 段带消息号)一条消息一个包,可能连发多个
10ZXMSZXMC506 MessageHistoryDone条数收尾;客户端按 来源+消息号 去重
ZXMC:Conline → ZXMS:CBack → ZXMS:ServerIdent → ZXMS:ServerName → ZXMC:AccountLogin → ZXMS:AccountLoginAck → ZXMS:ServerConfig → ZXMC:MessageHistoryReq → ZXMS:MessageHistory → ZXMS:MessageHistoryDone

B. 子服连官方端(ZXMS → ZXMOS)

子服启动时若 connectOS=1 就连官方端:100 上线 → 101 回执 → 双方 200/201 互报身份 → 官方端发起 520 挑战,子服 521 证明自己。

步发送端接收端协议码负载这一步做什么
1ZXMSZXMOS100 SOnline子服账号|端口|名称子服上线
2ZXMOSZXMS101 SBack—收到
3ZXMOSZXMS200 ServerIdentZXMOS官方端报身份
4ZXMOSZXMS201 ServerName官方端名称下发给子服(只读 ozname)
5ZXMOSZXMS520 OfficialChallenge32 位十六进制 nonce要证明“你是官方服务端”;只有已登录的连接才会收到
6ZXMSZXMOS521 OfficialProofBase64(lic)|nonce|HMAC-SHA256拿不出合法证明就回 err|原因(例如 err|development)
ZXMS:SOnline → ZXMOS:SBack → ZXMOS:ServerIdent → ZXMOS:ServerName → ZXMOS:OfficialChallenge → ZXMS:OfficialProof

C. 官方端发公告(逐跳转发)

ZXMOS 只发给子服;子服不解析正文,原样转给自己名下所有客户端。

步发送端接收端协议码负载这一步做什么
1ZXMOSZXMS500 Notice卡片:种类|标题|正文|来源|主动作|次动作|选项官方公告
2ZXMSZXMC500 Notice同一张卡片子服把它转给名下每个客户端(单向,不等回执)
ZXMOS:Notice → ZXMS:Notice

D. 定向推送(按账号过滤)

每跳都按目标账号本地过滤:命中才投,不命中静默丢弃。ZXMOS 的 push 命令支持 @账号 / @clients:子服名 / @servers。

步发送端接收端协议码负载这一步做什么
1ZXMOSZXMS501 Push目标账号|卡片官方端推一条
2ZXMSZXMC501 Push目标账号|卡片子服只把它发给这个账号,其他人收不到
ZXMOS:Push → ZXMS:Push

E. 玩家点消息卡片上的按钮

客户端把“点了哪个动作 + 填了什么 + 原卡片”一起回给服务端,服务端据此知道是哪张卡片。

步发送端接收端协议码负载这一步做什么
1ZXMCZXMS502 CardAction动作|输入|原卡片动作 = 按钮文案(下拉框固定“选择”),输入 = 填空内容
2ZXMSZXMC503 CardActionAckok|提示文本 或 err|原因回执
3ZXMSZXMOS502 CardAction动作|输入|原卡片若卡片来源是 ZXMOS,子服把它转给官方端(转发时负载前面多一段序号)
ZXMC:CardAction → ZXMS:CardActionAck → ZXMS:CardAction

F. 历史补发(两路合并)

子服自己也有存档(srvmsgdays):505 到达时,先把官方端那路要回来,再把自己存档的合并进去,统一按 504 发、506 收尾。

步发送端接收端协议码负载这一步做什么
1ZXMCZXMS505 MessageHistoryReqclient / self要历史
2ZXMSZXMOS505 MessageHistoryReqself子服替玩家向官方端要(中转为 client)
3ZXMOSZXMS504 MessageHistory卡片原文 + 消息号官方端逐条回
4ZXMSZXMC504 MessageHistory本服存档 + 官方给的历史(合并去重)两路合并后逐条发
5ZXMSZXMC506 MessageHistoryDone条数收尾
ZXMC:MessageHistoryReq → ZXMS:MessageHistoryReq → ZXMOS:MessageHistory → ZXMS:MessageHistory → ZXMS:MessageHistoryDone

G. 子服改名(611/612)

由控制台 osuser 命令触发;官方端校验新名可用后回执,子服把本地账号名与密码一起换掉。

步发送端接收端协议码负载这一步做什么
1ZXMSZXMOS611 AccountRename旧名|新名|密码密文|机器码改名请求
2ZXMOSZXMS612 AccountRenameAckok|新名 或 err|原因回执
ZXMS:AccountRename → ZXMOS:AccountRenameAck

H. 断线与重连

子服掉线后不会自动重发本地存档,等客户端下次 505 再补;控制台 net reconnect 可以立刻重连官方端。

步发送端接收端协议码负载这一步做什么
1ZXMSZXMOS100 SOnline子服账号|端口|名称重连后重新走一遍 100 上线
2ZXMOSZXMS101 SBack—收到
3ZXMSZXMC504 MessageHistory本服存档官方端不在线时,玩家仍能收到本服存档的消息
ZXMS:SOnline → ZXMOS:SBack → ZXMS:MessageHistory
