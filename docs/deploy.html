第 4 页:部署与运维

从工作区里的打包脚本、交付包结构、服务器目录和真实踩过的坑整理:怎么出包、怎么发、怎么改配置、怎么封人、怎么备份恢复。

① 打包脚本一览

脚本作用产物命令
_publish-aot.ps1把 ZXMC / ZXMS / ZXMOS / ZXMTL 用 AOT 发布并组装成交付包,再给 exe 签名_aot\pack\(1-官方服务端 ZXMOS / 2-子服务端 ZXMS / 3-客户端 ZXMC / 4-许可证工具 ZXMTL / 说明.txt)pwsh -NoProfile -File _publish-aot.ps1
_build-installer.ps1出客户端安装包:MSI(全机器安装)+ 便携 ZIP + 子服务端 ZIP_installer\out\ 与 桌面\ZXM-AOT-测试\安装包\(含 SHA256.txt)pwsh -File _build-installer.ps1 -Version 0.2.0
_pack-oserver.ps1打「全新未使用」的 ZXMOS 部署包(含 lic),并做自检:无证被拒/有证能监听_oserver\ZXMOS-官方服务端-*.zip(→ 桌面\ZXM-AOT-测试\官方服务端)pwsh -File _pack-oserver.ps1 -Version 0.2.0
_pack-site.ps1把官网打包成 zip(方便传宝塔),同时刷新下载页与日志页_installer\out\zxm-website.zippwsh -File _pack-site.ps1
_gen-site-download.ps1按 _installer\out 里的实际文件生成下载页(版本/大小/SHA256/链接)zxm-website\download.htmlpwsh -File _gen-site-download.ps1 -Version a0.2.0 -Tag a0.2.0
_gen-site-changelog.ps1从工作区的更新日志 md 生成 changelog 页zxm-website\changelog.htmlpwsh -File _gen-site-changelog.ps1
_sign.ps1用本机自签证书给 exe / MSI 签名,并装进本机信任区被签的文件(签名者 CN=ZincXManager 开发签名)pwsh -File _sign.ps1
_refresh-desktop.ps1把 _aot\pack 同步到桌面交付包,保留现场的 config.ini / 日志桌面\ZXM-AOT-测试\pwsh -File _refresh-desktop.ps1
_backup-repos.ps1两个仓库 + 程序 + 安装包 + 证书密钥 整包备份到 U 盘,并逐项校验U盘\ZXM备份\<时间戳>\pwsh -File _backup-repos.ps1(双击 备份到U盘.cmd 亦可)

② 交付包结构

_aot\pack\
├─ 1-官方服务端 ZXMOS\ ZincXManagerOServer.exe + config.ini
├─ 2-子服务端 ZXMS\    ZincXManagerServer.exe + config.ini
├─ 3-客户端 ZXMC\      ZincXManagerClient.exe + av_libglesv2.dll + libHarfBuzzSharp.dll + libSkiaSharp.dll + config.ini
├─ 4-许可证工具 ZXMTL\ ZincXManagerLicTool.exe
└─ 说明.txt

三端都是自包含 AOT 单文件,目标机不用装 .NET;客户端的三个 dll 是 Skia / HarfBuzz / OpenGL 渲染依赖,必须跟着一起拷。

⑤ 配置与迁移

场景键 / 机制行为
connectOS 语义变更configver老配置没有 configver 时,启动会做一次性迁移:老的 0(连)改成 1(连),并写入 configver=2
显示名跟随账号名linkname默认 1 = 名称与官方账号名一致;设 0 = 分开设置
半透明不透明度alpha客户端首次运行把默认 90 写进 config.ini;之后只读配置,不再硬编码
服务端码servercode缺失或格式不对就生成 32 位十六进制并写回;老部署缺它会提示「身份不一致」风险
天数配置msgdays / srvmsgdays客户端留多久 / 本服存档留多久(补发用),缺项自动写默认 7
对端校验officialcheck1 = 对端不是官方就断开;0 = 只警告继续

⑦ 备份与恢复

备份内容位置说明
公开仓 ZincXManagerU盘\ZXM备份\<时间戳>\ZincXManager整包(排除 bin/obj/.vs/node_modules),含 .git,可直接 git 打开
私有仓 ZincXManager-OfficialU盘\ZXM备份\<时间戳>\ZincXManager-Official同上
程序(ZXMOS/ZXMS/ZXMC/ZXMTL)…\程序\打包程序_aot\pack 全量;以后 ZXMM 放进同一目录会自动带上
安装包…\程序\安装包MSI / 便携 ZIP / 子服 ZIP
官方服务端部署包…\程序\官方服务端部署包ZXMOS 的 zip
证书 / 私钥 / lic…\证书密钥ZXMOS 官方签名密钥对(pem)、official.lic / official-local.lic、代码签名 .cer(+pfx)

校验:每个仓库都比「文件数 + 总字节 + git HEAD」;结果写进 MANIFEST.txt。只保留最近 3 份(-Keep 3)。代码签名 pfx 的口令不写进备份,恢复时要输入当初设置的口令;非交互跑(-NonInteractive)只备 .cer。

⑧ 常见故障排查

现象原因处理
ZXMS 启动报「监听失败,通常每个套接字地址只允许使用一次」czport 被别的进程(或另一个 ZXMS)占了换 czport 或先停掉占用的进程
ZXMOS 起来就退出,日志里有「没找到许可证」official.lic 不在 exe 同目录,或机器码对不上把签好的 official.lic 放到 exe 同目录;测试时可临时设 ZXM_ALLOW_UNOFFICIAL=1
官网改了但浏览器还是旧页面GitHub Pages / CDN 有缓存等 1 分钟硬刷新;服务器站点是直接读文件,不需要等
用 jsDelivr 按 commit 拉文件拿到旧内容CDN 边缘缓存改用 raw.githubusercontent 或 Pages 地址
从 git 取下来的页面和本地大小不一致core.autocrlf=true 把 CRLF 换成 LF内容一致,大小差 = 行数;比对内容而不是字节数
宝塔「上传文件」点了不出选择框面板上传组件在 Edge 下不弹窗改用 计划任务 → Cmd脚本 拉取,或文件管理器「编辑」里粘贴保存
宝塔计划任务里串多条 curl 时后几条没执行前一条失败/超时,&& 链中断一条命令一个文件,或改用 & 并延长等待
远程桌面里往控制台打字没反应RDP 焦点/输入被转发到别的窗口直接用 Win+R 跑短命令,或在目标机建 .cmd 双击
